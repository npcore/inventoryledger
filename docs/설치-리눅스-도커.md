# 사내 리눅스 서버 설치 (Docker)

## 0. 준비

서버에 Docker Engine과 Compose 플러그인이 있어야 합니다.

```bash
docker --version
docker compose version
```

없으면 배포판에 맞게 설치합니다 (https://docs.docker.com/engine/install/). Ubuntu 기준:

```bash
curl -fsSL https://get.docker.com | sudo sh
```

> **현재 설치 위치 (2026-10-25):** `hansc-spark`(172.31.109.242)의 `~/inventoryledger`에 설치되어 있습니다.
> hansc 계정은 docker 그룹에 속하고 UID가 1000이라 컨테이너 사용자와 같습니다. 그래서 아래 명령에서 `sudo`와 `chown` 없이
> `~/inventoryledger` 경로로 실행하면 됩니다. 예: `cd ~/inventoryledger && docker compose up -d --build`

## 1. 프로그램 복사

내 PC(Mac)에서 서버로 복사합니다. 서버 주소와 계정은 실제 값으로 바꾸세요.

```bash
# Mac에서 실행
rsync -av --exclude .venv --exclude data --exclude backups --exclude .git --exclude tests \
  ~/projects/inventoryledger/  사용자@서버주소:/opt/inventoryledger/
```

> 나중에 Git 저장소(GitHub, 사내 GitLab 등)를 만들면 `git clone`/`git pull`로 바꾸는 편이 편합니다.

## 2. 데이터 폴더 만들기

컨테이너는 보안상 일반 사용자(UID 1000)로 실행됩니다. 그래서 데이터 폴더 소유자를 맞춰야 합니다.

```bash
cd /opt/inventoryledger
sudo mkdir -p data backups
sudo chown 1000:1000 data
```

## 3. 빌드하고 실행

```bash
cd /opt/inventoryledger
sudo docker compose up -d --build
sudo docker compose ps          # STATUS가 healthy면 정상
```

브라우저에서 `http://서버주소:8000`에 접속합니다.

방화벽을 쓰면 8000 포트를 사내망에만 엽니다.

```bash
# Ubuntu (ufw) 예시: 사내 대역이 192.168.0.0/24 인 경우
sudo ufw allow from 192.168.0.0/24 to any port 8000 proto tcp
```

## 4. 처음 설정

1. 처음 접속하면 **관리자 계정 만들기** 화면이 나옵니다
2. [결산 (실사·수불부)] 메뉴에서 기존 결산파일 `재고수불 결산파일(2026.2Q)_엔피코어.xls`를 올립니다
3. [다음 분기 만들기]를 누르면 2026.3Q가 생깁니다. 이제 7~9월 입고를 등록하고 실사를 입력하면 됩니다
4. [사용자] 메뉴에서 직원 계정을 추가합니다

## 5. 백업 (꼭 설정하세요)

모든 데이터는 `data/inventory.db` 파일 하나에 들어 있습니다. 백업 스크립트는 프로그램이 실행 중이어도 안전하게 복사하며, 기본으로 90일치를 보관합니다.

```bash
sudo /opt/inventoryledger/scripts/backup.sh     # backups/inventory-YYYYMMDD-HHMMSS.db 생성
```

매일 새벽 2시에 자동으로 백업하려면 다음처럼 설정합니다.

```bash
sudo crontab -e
# 아래 한 줄 추가
0 2 * * * /opt/inventoryledger/scripts/backup.sh >> /opt/inventoryledger/backups/backup.log 2>&1
```

`backups/` 폴더는 가능하면 NAS나 다른 서버에도 한 번 더 복사해 두세요. 서버 디스크가 고장 나면 같이 사라지기 때문입니다.

### 백업에서 복구

```bash
cd /opt/inventoryledger
sudo docker compose stop
sudo cp backups/inventory-20261231-020000.db data/inventory.db
sudo chown 1000:1000 data/inventory.db
sudo docker compose start
```

## 6. 프로그램 업데이트

새 버전을 1번처럼 다시 복사한 다음 실행합니다. `data/`는 그대로 유지됩니다.

```bash
cd /opt/inventoryledger
sudo ./scripts/backup.sh                 # 업데이트 전 백업
sudo docker compose up -d --build
```

## 7. 자주 쓰는 명령

| 할 일 | 명령 |
|---|---|
| 상태 확인 | `sudo docker compose ps` |
| 로그 보기 | `sudo docker compose logs -f --tail 100` |
| 재시작 | `sudo docker compose restart` |
| 중지 / 시작 | `sudo docker compose stop` / `sudo docker compose start` |

서버를 재부팅해도 컨테이너는 자동으로 다시 켜집니다(`restart: unless-stopped`).

## 8. 외부 접속 (공유기 포트포워딩 + HTTPS)

`caddy` 컨테이너가 80/443 포트로 HTTPS를 제공하고, Let's Encrypt 인증서를 자동으로 받고 갱신합니다.

1. 서버의 `~/inventoryledger/.env`에 외부 주소를 적습니다. 도메인이 없으면 공인 IP로 만든 sslip.io 주소를 씁니다 (공인 IP가 124.57.58.88이면 아래처럼 적음)
   ```
   SITE_ADDRESS=124-57-58-88.sslip.io
   ```
2. 공유기 관리 화면의 포트포워딩 메뉴에서 **TCP 80 → 서버IP:80**, **TCP 443 → 서버IP:443**을 추가합니다. 8000번은 추가하지 않습니다
3. 공유기 DHCP 설정에서 서버 IP를 고정합니다 (서버 IP가 바뀌면 포워딩이 끊기기 때문)
4. `docker compose up -d` 후 `docker compose logs caddy`에 `certificate obtained successfully`가 보이면 `https://외부주소`로 접속됩니다

> 공인 IP가 바뀌면 sslip.io 주소도 바뀝니다. IP가 자주 바뀐다면 회사 도메인(예: `stock.npcore.com`)의 A 레코드를 공인 IP로 지정하고 `.env`의 `SITE_ADDRESS`를 그 도메인으로 바꾸세요.
> 사내에서 외부 주소로 접속이 안 되는 공유기가 있습니다 (NAT 루프백 미지원). 그때는 사내에서는 `http://서버IP:8000`을 쓰면 됩니다.

## 문제 해결

- **`unable to open database file` 또는 `Permission denied`**: 2번의 `sudo chown 1000:1000 data`를 빠뜨린 경우입니다
- **포트 8000을 이미 쓰는 경우**: `docker-compose.yml`의 `"8000:8000"`을 `"8080:8000"`처럼 앞 숫자만 바꿉니다
- **관리자 비밀번호를 잊은 경우**: 다른 관리자가 [사용자] 메뉴에서 새 비밀번호를 지정합니다. 관리자가 한 명뿐이면 개발 담당자에게 요청하세요
- **로그인이 자꾸 풀리는 경우**: `data/secret.key`가 지워졌거나 바뀐 경우입니다. 다시 로그인하면 됩니다

## 참고

- 사내에서는 `http://서버주소:8000`으로 접속합니다. 8000 포트를 인터넷에 직접 열면 안 됩니다 (비밀번호가 암호화되지 않은 채 전송됨)
- 시간대는 한국 시간(Asia/Seoul)으로 맞춰 두었습니다. 입고일 기본값이 오늘 날짜로 들어갑니다
